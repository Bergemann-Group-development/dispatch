## 4. Own <3D> averages with density (decision 5)

**Tool.** tumult already had the averaging: `AtmosClass.to_dispatch1d_atmos` averages a
3D atmosphere on log tau_500 surfaces (geometric means of T, n_e, rho) and writes
dispatch.x's `text` format, which carries density.
- `jobs/avg3d.py` pools the columns of 10 snapshots per model, evenly spaced over the
  model's sequence.
- The snapshots go through atmosphere-only dispatch.x runs (`make_nml.py avg3d`): the
  `3d` preset's 30x30x96 resampling, the model's composition, a 0.5 A window. These take
  about 20 s each.
- The 1D runs read the file with `atmos_format='text' use_ne=F amr='T'`: rho given, n_e

## 7. A: O departures in joint and separate solves

**Setup.** Local gfortran 1D runs on the solar MARCS model (p5777 g4.4, nz=64), o41f
with convlim 1e-5:
- O alone, O+Mg, O+Fe, O+Mg+Fe;
- O alone and O+Mg, O+Fe again with `&rt_iteration_params include_absmet=F`.

**Which levels, which depths.** Of the 41 O levels, only the O II ground (level 40,
2p3 4S) moves noticeably, at the top of the model:

| O departures, log b difference | max (level 40, log tau -5.6) | other levels, max | at log tau -1 |
|---|---|---|---|
| O+Fe - O | -0.179 | 4p 5P -0.049, 3p 3P2 -0.032 | <= 0.006 |
| O+Mg - O | -0.062 | 4f 5F -0.007 | <= 0.001 |
| O+Mg+Fe - O | -0.184 | 4p 5P -0.050 | <= 0.006 |
| O (no absmet) - O | +0.249 | 4f 5F +0.039 | <= 0.010 |
| O+Fe - O, both without absmet | -0.231 | 4p 5P -0.053 | <= 0.005 |
| O+Mg - O, both without absmet | -0.034 | | <= 0.002 |

**Mechanism.** The O ionisation balance at log tau < -5 is set by the UV radiation
field, through photoionisation from the O I 3s and 3p levels with edges at 2800-4300 A.
What changes that field is how the other elements' opacity is represented.
- **In a separate O run**, Fe and Mg enter only as LTE background: their bound-free
  continua from `absdat`, and their lines inside the solar `absmet` table.
- **In a joint run**, the Fe (Mg) atom replaces its background continua with NLTE ones
  (`exclude_double_continua`) and adds its 12635 (Mg: 300+) lines in NLTE. Its lines
  are also still in absmet: absmet is a sum over all species and cannot drop one.
- **So the joint run is not the more complete one: it counts Fe's lines twice.** More
  UV opacity means less O ionisation at the top, hence the lower O II population.
- Without absmet the Fe effect stays about the same (-0.23), and removing absmet alone
  moves O II by +0.25. So the O top layers react to any UV line opacity, at the
  0.2 dex level.
- None of this reaches the layers where O I lines form: below log tau -2 every level
  changes by <= 0.006 dex.

**Verdict.** Separate solves are adequate for O, as long as the background represents
the other elements' line opacity once and at the right composition (section 9). A joint
solve would need absmet without the NLTE species, which does not exist (section 9).

## 9. C: background line opacity in the NLTE iteration

**How the code includes it.**
- `&rt_iteration_params include_absmet` defaults to T, so every iteration pass adds the
  sampled metal-line opacity of the `absmet` table. The line list (`include_linelist`)
  defaults to F there.
- **The table** (`HOP/osmet_mod.f90`): MARCS/Turbospectrum `add_metal_opac` format,
  unformatted sequential.
  - Two text records, a species list (184 codes, 100 = H I to 9201 = U II, including
    800/801 O I/II, 1200/1201 Mg I/II, 2600/2601 Fe I/II).
  - xiturb = 1 km/s, 18 log P6 nodes (10^-8..10^9), 17 T nodes (500-30000 K).
  - Then one record per wavenumber: 153910 points from 910 A to 200 um, every 0.25 A at
    5000 A, i.e. R = 20000, holding log10 kappa per gram.
  - It is interpolated bilinearly in (log P6, T) and linearly in frequency, times rho.
  - `mnu` caps the frequencies at 154000.
- **The campaign** used `input/absmet_files/absmet`, a solar table (record 11:
  abundances 12, 10.93, ...), for every model down to [Fe/H] = -4. The table carries no
  metallicity scaling. So a metal-poor departure run saw solar-metallicity line
  blanketing, and every atom's own lines twice: in absmet and from the atom.
- **The metal-poor tables** (m-1, -2, -3, alpha +0.4) exist locally, but are
  big-endian. The reader's byte-order retry fired only on end of file, and gfortran
  reports a different error, so they could not be read. Fixed in d2f3eabfb (retry on
  any failed header read). A solar-absmet O run is byte-identical. The ifort build is
  queued (2178343, `$C/bin/23675093a`). The tables are now in `$C/work/absmet/`.

**Test.** As in section 8, on the `grid` quadrature, against solar absmet:
- `noabs`: no background lines in the iteration;
- `mabs`: the [Fe/H]-matched table;
- `llit`: no absmet, the detailed FGK line list (VALD 1000-25500 A plus molecules) in
  the iteration pass. The atom's own species are excluded from the list as in the SEDs,
  so nothing is counted twice and the composition is the model's.

| Model | Atom | noabs | mabs | llit |
|---|---|---|---|---|
| [Fe/H] = -3 giant | Fe I | +0.261 (0.21..0.31) | +0.206 (0.17..0.25) | +0.200 (0.16..0.24) |
| | Fe II | +0.142 | +0.115 | +0.119 |
| | Mg I | +0.117 | +0.086 | +0.080 |
| | O | 0.000 | 0.000 | 0.000 |
| Sun | Fe I | +0.031 | (solar table) | +0.011 |
| | Fe II | +0.013 | | +0.005 |
| | Mg I | +0.033 | | +0.003 |
| cool dwarf | Fe, Mg | <= 0.002 | | <= 0.0003 |
| [Fe/H] = -2 giant | | *pending* | | |

- **Solar blanketing in metal-poor runs.** At [Fe/H] = -3 the solar table blankets the
  UV about 1000x too strongly. That damps the overionisation that drives NLTE Fe I, and
  the Fe I corrections come out 0.2 dex too small (Mg 0.08 dex).
- **Matched table against the line list.** The matched table and the detailed line list
  agree to 0.006 dex (Fe I, Mg), so the table's R = 20000 sampling is adequate for the
  departures.
- **The residual at solar metallicity.** The 0.011 dex (Fe I) between the line list and
  the solar table in the Sun is mostly the double counting of Fe's own lines in absmet.
- **Cost.** The line list in the iteration costs 3-5x for Fe (Sun 153 -> ~600 s,
  giant 166 -> 506 s, dwarf 84 -> 425 s) and about 80x for Mg and O (4 -> 370-440 s).
  A matched table costs nothing extra.

**Decision taken for new departure runs.** The matched absmet table: `make_nml.py
absmet_for`, the nearest of solar, -1, -2, -3. [Fe/H] = -4 takes the -3 table, which
still over-blankets by 10x. Its effect is bounded by the noabs-mabs difference at -3:
0.03-0.06 dex.

**A better table: design, not built.** An absmet table without the NLTE species, at the
model's composition, would remove both the double counting and the -4 gap. Procedure:
- HOP line opacity per gram from the VALD list minus the species, at the table's
  (P6, T) nodes. Each node is solved for (rho, n_e) with HOP's EOS at the target
  composition.
- Sampled at R >= 20000 from 910 A to 25 um.
- Written in the format above.

Costs and blockers:
- A finer step needs `mnu` in `osmet_mod` raised, a code change.
- About 300 nodes x 3e5 wavelengths of HOP opacity: estimated 1 h per composition.

Given the 0.006 dex agreement of the existing matched tables with the line list, this is
for the double counting (0.01 dex at solar metallicity) and for [Fe/H] = -4 only.

**What it means for existing departures.** All of batch 2 (1418 MARCS + 241 <3D>/twin
runs), the pilot 1D and <3D> runs and the 3D Mg and Fe pilot runs used solar absmet.
- At [Fe/H] >= -0.5 that is right up to the 0.01 dex double counting.
- At [Fe/H] <= -1 the Delta_NLTE maps are biased low. Fe I: -0.2 dex at -3; *pending*
  at -2.
